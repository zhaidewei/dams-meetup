§1项目背景

目标场景：2026-05-09 12:45–18:00（Europe/Amsterdam），200–300 名荷兰华人数据从业者线下 meetup。

核心价值：让参会者把"求助 / 组队 / 内推 / 观点 / Q&A"广播给全场 200 人，而不是只能跟身边 5 个人聊。配合 AI 撮合，主动推荐"应该跟谁聊"。

边界：单场即弃，无多租户、无邮件基础设施。活动结束 7 天内可通过恢复链接登录看回顾。

已上线：自定义域名 live.nl-dams.com，部署在朋友 Cloudflare 账户的 Workers + Supabase（数据 + Realtime + Edge Functions + pg_cron）。

§2当前业务流

普通参会者
扫 QR 进入→ 输活动密码→ 浏览 timeline（按 LIVE 板块或 lounge）→ 发帖（含 tags + 私下 AI 撮合委托）→ 点头像看 UserCard 复制联系方式 / DM→ 收到点赞 / 回复 / AI 推荐→ /me 看自己状态

浏览器 UUID 即身份。换设备可走 /me 复制恢复链接 7 天内还原；首次委托 AI 撮合需勾选 consent（同意一次永不再问）。

嘉宾（VIP）
vip-login（用户名+密码）→ 实名 + 职位自动展示+ 发起投票（单/多选 + 隐藏结果）+ 作为 QA host 接收提问

~10 名嘉宾，主办方预录入用户名+密码。1 个嘉宾 token ↔ 1 个 user 行，跨设备登录共享同一身份。

主办方（admin）
admin 密码登录→ /screen 侧边栏控制台→ 切 LIVE 板块（lounge / p1 / p2 / breakout / panel）→ 切 screen_mode（default / qa / lottery）→ 控 QA host/ 抽奖

event_state 单行表做 state container；admin override 优先于板块时间窗自动切换。

现场主屏 / 投影
/screen 路由→ 焦点帖 + 网格 layout→ 活动投票 / QA / 抽奖全屏接管→ 右下 QR + 在线人数

Realtime 触发刷新（Supabase broadcast）+ 60s 兜底 interval；max-width 1400px 防焦点散开。

§4架构概览

graph LR Browser["浏览器
(uid + pw cookie)"] -->|HTTPS| CF["Cloudflare Workers
(live.nl-dams.com)"] CF -->|service_role key| Supa[("Supabase Postgres")] Browser -.->|anon key 只读 Realtime| Supa Cron[("pg_cron 5min")] --> Edge["Edge Function 'match'
DeepSeek 撮合"] Edge -->|consent gate| Supa Admin["admin cookie"] --> CF

关键决策

  • 无 Auth：浏览器 UUID + cookie 即身份。降低参与摩擦
  • 服务端写 + 公开 RLS 读：所有写经 Server Actions（service_role），客户端 anon key 只做 Realtime 订阅
  • 恢复链接：每个 user 行有 recovery_token，URL 形式跨设备 7 天内换回身份
  • VIP 跨设备一致：1 vip_token ↔ 1 user 行
  • 撮合方案 F''：发帖时附暗字段，AI 以 reply 形式内联回复
  • AI consent (issue #34)：用户首次委托 AI 时显式同意，门票化两路数据流
  • 状态机 in event_state：单行表（id=1）做 state container，admin 通过控制台改
  • iPhone Chrome 抗坑：所有写操作走 form action progressive enhancement

技术栈

  • Next.js 16.2.4（App Router · Server Components · Server Actions · Turbopack）
  • Supabase（Postgres + Realtime + Edge Functions + pg_cron）
  • Cloudflare Workers via @opennextjs/cloudflare
  • TypeScript · Tailwind v4 · Vitest · lucide-react
  • DeepSeek（撮合 LLM）

§7设计澄清 · AI 撮合数据流（5/6 含 consent gate）

"AI 撮合是不是用 RAG 拿所有数据？"
答：不是 RAG，是"胖 prompt"——把候选池一次性塞进上下文让 LLM 自己挑。详见 matching-design.md。

当前数据流（已 deploy）

[每 5 min pg_cron 触发 Edge Function 'match']
  ↓
1. fetchCandidates: 从 post_match_intents 拉未生成 AI reply 的 post
   （写入端 createPostAction 已 gate 在 ai_consent_at 上）
2. fetchProfiles: posts inner join users where ai_consent_at IS NOT NULL
   聚合最近 500 条帖成"画像"
3. buildPrompt 拼装：
   ┌─────────────────────────────────────────┐
   │ ## 候选帖子（含暗需求）                  │
   │  post_id=X | user_id | 板块 | body      │
   │  暗需求: ...                             │
   │                                          │
   │ ## 全场用户画像                          │
   │  user_id | display_name · affiliation   │
   │  - [板块][tags] body 摘要               │
   │  ... ×N                                 │
   └─────────────────────────────────────────┘
  ↓
4. callDeepSeek → JSON [{post_id, user_id, reason}]
5. INSERT INTO replies (is_ai=true, visibility='author_only',
                        mentioned_user_id, body=reason)
6. UPDATE match_runs SET status='success', ...

5/6 新增 · consent gate（issue #34）

关卡实现
用户公开发帖被聚合成 AI 画像 consent 后才进 fetchProfiles inner join + not is null
用户私下需求 (match_intent) 发 DeepSeek consent 后才写 createPostAction 写 post_match_intents 前 double-check
UI 入口 inline checkbox 嵌在 PostComposer AI 撮合 box 里，piggyback 在 post submit；同意一次永久记住，拒绝下次再问
Redact 兜底 仍生效 redactContacts() 邮箱/URL/≥10 数字 → [已隐藏]
带空格手机号 / 微信号 残余风险 正则无法可靠捕获，consent 文案 + UI 提示作主防线

实际发往 DeepSeek 的字段：

  • candidate 帖（≤50 条）：post_id / user_id (UUID) / 板块 / body (redacted) / tags / 暗需求 (redacted)
  • 全场画像（≤500 条聚合，仅已同意者）：user_id / display_name (昵称或嘉宾实名) / affiliation (公司或职位) / 最近 5 条帖摘要 (redacted)
  • 不发：contact_handle、recovery_token、vip 密码、replies、likes、poll_votes、私信、时间戳

§9怎么参与

仓库 public，PR 直接发。先扫这几篇文档建立背景：

CLAUDE.md docs/architecture.md docs/schema.md docs/dev-setup.md docs/matching-design.md docs/progress.md

cd dams-meetup
npm install
# 找 dewei 拿 Supabase / 活动密码 / DeepSeek 凭据
npm run dev      # http://localhost:3000

凭据走 macOS Keychain（脚本 scripts/dev.sh 注入）；不写 .env.local。Linux/Win 需自己改注入方式。

  • 架构 / 业务流挑战：直接在 GitHub 开 Issue 讨论。希望挑战的都挑战。
  • 新功能 / 改动：fork → PR。小改动直接发，大改先开 Issue 对齐。

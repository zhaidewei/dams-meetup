1.2 负载放大模式

每条写入（发帖 / 点赞 / 回复）触发 Supabase Realtime broadcast 给所有在线订阅者。 每个客户端收到广播后 router.refresh() 重渲染整张 timeline，重新打 5+ 个 Supabase 查询。 N 个用户的总负载 ≈ O(N²)。这是要测的核心曲线。

4. 最关键的发现

4.1 Free tier 的真正天花板是 PostgREST 连接池，不是 CPU

200 并发下 Supabase Observability 显示：

  • 10,644 个 503 错误 / 10 分钟，集中在 /rest/v1/posts 和 /rest/v1/event_state
  • CPU usage 大部分时间空闲（2.48%）
  • 内存 906 MB / 1 GB，磁盘 IO 1.1 MB/s — 都健康
  • 但 DB Connections 40/60 (66.7%)，PostgREST 池被打满，单条 user 查询排队 50 秒才执行

诊断关键：fetchFeed 查 posts 失败时会兜底返回空数组 + 200 OK，所以 CF Worker 看不到 5xx，但用户实际体验是空白页。比直接 5xx 还糟。

4.2 优化生效有延迟，第一轮测试容易抢跑

③ → ④ 仅相隔几十分钟，配置完全相同，但 p50 从 14.6s 跳到 4.3s（3.4× 改善）。差异来源：

  • Cloudflare Workers Builds 从 git push 到部署需要 3–5 分钟
  • Supabase compute resize 调度→实际应用有 5–10 分钟窗口期
  • 各层缓存 / 连接池冷启动

教训：升级类操作之后等 10 分钟再测，否则容易得到悲观假象，引发不必要的进一步优化。

4.3 单机模拟 200 个虚拟用户存在客户端污染

同时段：Mac 跑 4 进程压测 + Chrome 访问 → Chrome 卡顿；同样的 Chrome 在手机上访问 → 流畅。说明压测进程把本机的 TLS 握手 / 网络栈 / CPU 都吃了一部分，报告的延迟里有一部分是 Mac 自己的瓶颈。

真实活动里 250 个真实手机分布在不同蜂窝/Wi-Fi 网络上，体感会比测试数据更流畅。

6. 风险与未验证项

  1. Realtime 长连接稳定性：单次测试 180s 没暴露长时间 WebSocket 重连问题，活动 6h 可能出现意外。建议活动当天指定 1 名工作人员看 Supabase Realtime metrics。
  2. VIP 投票峰值：未单独压测投票场景。VIP 起一个 poll 时所有人同时打开投票，瞬间产生 ~250 个 poll_votes 写入，未在本次时间内验证。
  3. AI 撮合 Edge Function：不在临界路径，DeepSeek 故障也只影响「撮合」侧栏，feed 不受影响。不阻塞 ship。
  4. 多机协同压测：5/8 计划由朋友们多机一起跑一轮，验证去除单机污染后的真实性能。

7. 进一步优化（如需）

当前已经 ship-ready，以下选项备查：

  • fetchFeed 改 RPC：把 4 个并行查询合成单个 stored procedure，再省 3 个 round-trip。预期 p50 再降 30-50%。工作量 1–2h。
  • Supabase compute 升 MEDIUM：max_conn 120, PostgREST pool ~40。$0.08/h × 6h ≈ $0.48。预期 p50 再降 ~20%。
  • FeedRealtime debounce 2.5s → 5s：感知延迟可接受，fanout 再减半。零成本。

8. 压测框架本身

仓库内 loadtest/ 目录：

  • run.mjs — 入口，parseArgs 读 CLI flag，spawn N 个 VirtualUser
  • user.mjs — VirtualUser 完整生命周期：密码门 → /feed → Realtime 订阅 → 90/10 读写循环
  • stats.mjs — counter + reservoir-sampled 直方图，输出 p50/p95/p99
  • cleanup.mjs — 按 PID 前缀删测试数据，FK CASCADE 自动清下游
  • aggregate.mjs — 合并多进程 / 多机的 stats JSON
  • seed.mjs — 注入基线 200 users / 400 posts / 1500 likes / 500 replies
  • friend.sh + FRIENDS.md — 朋友帮忙跑测试的 wrapper（不依赖 macOS Keychain）

压测框架的设计文档见 docs/loadtest.md。
